# Team review guide

Start with the pages your team owns. Expand a microfeature, read the four explanations, then verify its availability, scope and evidence. Use the parameter ID and permanent section link in feedback so an editor can apply the correction to the exact entry.

Download the review worksheet and add a reviewer, confirmed status, eligible plan, supported formats, precise limits, evidence URL, correction and decision. The worksheet is a blank review deliverable; this site does not silently collect or synchronise comments.

## Recommended review order

Product owners should validate delivery, room, AI, payment and CRM behaviour. Technical and integration owners should check connection methods, field mappings, API operations, limits and failure handling. Security and legal owners should review assurance wording and terms. Customer success should review help, onboarding and support commitments.

Approve a claim only when the exact wording matches the evidence. Keep unsupported requests visible as limitations and move roadmap ideas into a clearly separate roadmap process. Marketing should edit for readability after product scope is confirmed, then check the public site and profile consistency.
